# 环境伪装模块的设计与反检测对抗

> 分析对象：一个面向管理端应用的 Zygisk 模块与其配套的 kiosk/原生隐藏组件。
> 证据等级：A（模块源码）+ C（现场行为）。
> 配套阅读：[[research/login-chain-audit]]（登录链路审计）、[[research/postmortem]]（事故复盘）、[[16-permissions-device-identity]]（设备身份体系）。

## 一、结论速览

| 问题 | 答案 |
| --- | --- |
| 模块解决什么问题 | 让应用相信设备是原厂、未 root、已授权 |
| 有几组伪装 | 六组：系统属性、设备管理员、权限、检测规避、kiosk、日志弹窗 |
| 最核心的一组 | 设备管理员伪装——决定「系统异常，不可使用」是否弹出 |
| 安全底线是什么 | 所有危险 DPM 方法（锁屏/擦除/重启）全部空操作 |
| 最大的局限 | 只覆盖已知检测点；原生层与直接文件读取仍在覆盖外 |
| kiosk 怎么退出 | 音量键组合暗号，六秒内完成 |
| 一句话风险 | 伪装越完整，异常特征越明显 |

## 二、六组伪装

### 2.1 系统属性

通过 `resetprop` 改写启动属性，并持久化到开机脚本中，保证重启后仍生效。

| 属性 | 原值 → 伪装值 | 目的 |
| --- | --- | --- |
| 保修标志位 | `1 → 0` | 伪装成未解锁引导程序 |
| 完整性校验状态 | 已解锁状态 → 已验证状态 | 同上 |
| 引导锁状态 | 空 → 已锁定 | 同上 |
| vbmeta 设备状态 | 已解锁 → 已锁定 | 同上 |
| 系统版本号 | 新版 → 旧版（14/34） | 兼容旧判定 |
| 系统指纹 | 第三方系统值 → 原厂值 | 伪装成未刷机 |
| 产品名/描述 | 改为原厂值 | 同上 |

同时把设备序列号与 MAC 固定为原机真值——因为服务端记录的是原机值，用假值反而立刻暴露。

### 2.2 设备管理员伪装

这是整套模块的核心。判定链：

```text
DeviceActiveManager.isDeviceActivated()
  = isAdminActive() && isSDKActivated()
      → LicensePolicyProxy.isFreeLicenseActivated()
      → SamsungKnoxV3.hasPermission()
      → CustomDeviceManager.getInstance()
      → EnterpriseDeviceManager.getAPILevel()      // 第三方系统上抛 NoClassDefFoundError
```

最后一步是关键：第三方系统上没有厂商的企业管理 API，方法直接抛 `NoClassDefFoundError`，上层捕获后判定为「非受支持设备」，于是弹出「系统异常，不可使用」。

hook 表覆盖八个判定点，包括管理员激活状态、许可激活状态、Knox 权限、设备所有者状态、API Level 等。

**安全底线**：所有危险 DPM 方法全部改为空操作。

| 方法 | 处理 |
| --- | --- |
| `lockNow` | 空操作 |
| `wipeData` | 空操作 |
| `reboot` | 空操作 |
| 其他 DPM 危险方法 | 空操作 |

这条底线的意义：伪装可以让应用「以为自己是管理员」，但绝不能真的获得擦除设备的能力。**这是唯一一条不可妥协的设计约束。**

### 2.3 权限伪装

让应用相信已被授予以下权限：

| 权限 | 伪装方式 |
| --- | --- |
| 读取图片/视频/音频 | 查询返回 0 行游标（有权限但无数据） |
| 读取外部存储 | 同上 |
| 使用情况统计 | 返回空集合 |

刻意**不伪装**写外部存储——因为一旦伪装，应用会尝试真的写入，导致失败暴露。

「有权限但数据为空」是个巧妙的中间态：既不触发权限请求弹窗，也不暴露真实文件。

### 2.4 检测规避

| 检测项 | 处理 |
| --- | --- |
| 系统属性查询 | hook `getprop` 返回值 |
| 文件存在性检查 | `File.exists/isFile/isDirectory/canExecute/canRead` 对 root 相关路径全部返回 false |
| 命令执行 | `Runtime.exec("su")` 改为抛 ENOENT（见 §2.6） |
| 进程名扫描 | 过滤 `/proc/self/maps` 中的模块相关行 |
| 包名扫描 | 对模块自身与 kiosk 包执行 `pm unhide` |

原生层隐藏模块只过滤**目标应用**的 `maps` 文件，不影响其他进程——这是刻意的收窄，避免全局 hook 带来的稳定性问题。

### 2.5 kiosk 模式

| 行为 | 说明 |
| --- | --- |
| 白名单外前台即杀 | 检测到非白名单应用在前台，立即 force-stop |
| HOME 键直进登录页 | 拦截 HOME，导流到目标界面 |
| 导航栏/状态栏隐藏 | 消除退出路径 |
| 退出暗号 | 六秒内：音量+ ×3，音量- ×3 |
| 退出动作 | 解冻全部目标应用 → 恢复桌面/手势/锁屏/任务栏 → 解除锁屏设置禁用 → 灭屏六秒 → 三十秒冷却 |

退出流程里的「灭屏六秒」不是装饰：某些界面状态在亮屏时不会被重新计算，必须暗屏再亮才会刷新。冷却期用于防止重复触发。

### 2.6 su 语义的修正（关键细节）

早期的伪装是让 `su` 调用返回 false、退出码 1——这等于「有 su 但拒绝了」，本身就是一条异常信号。

正确的伪装是让 `su` **不存在**：

| 调用 | 伪装后的结果 |
| --- | --- |
| `Runtime.exec("su")` | 抛 `IOException: Cannot run program "su": error=2, No such file or directory` |
| `ProcessBuilder("su").start()` | 同上 |
| `sh -c "su ..."` | stderr `sh: su: not found`，退出码 127 |
| `which su` / `command -v su` | 空输出，退出码 1 |

配套：`File.exists` 对 `/su`、magisk、ksu、apatch、lsposed 等路径全部返回 false。

这条修正的价值在于：它把「异常但存在」改成了「正常且不存在」，两类现象在服务端看来完全不同。

### 2.7 日志权限弹窗自动拒绝

新版系统在授权日志访问时会弹一个系统对话框。处理方式：

1. hook 对话框的 `show()`；
2. 立即调用拒绝路径；
3. `finishAndRemoveTask()` 移除该界面。

三步必须在同一帧内完成，否则用户会看到一闪而过的弹窗。

## 三、状态面板

模块自带一个状态面板 Activity，用于查看当前伪装状态。数据来源两处：

| 来源 | 内容 |
| --- | --- |
| 外部存储的一个文本文件 | 各属性当前值 |
| 日志标签 `XHNativeHide` | 原生层过滤记录 |

面板的价值：伪装失败时不需要重新抓包，直接看面板即可定位是哪一项没生效。

## 四、登录模拟调试开关

模块提供一条**默认关闭**的调试路径：当外部存储存在某个标记文件时，把登录响应里的 `activated:false` 改为 true，并注入一个假令牌。

实测结论：主界面依赖服务端下发的两个会话字段，假值会触发 `illegal ciphers text` 错误。因此这个开关只能用于验证「激活判定链路」，不能真正进入主界面。

**这条记录本身很重要**：它证明了「伪造激活状态」不足以进入系统，因为后续通信还需要服务端认可的会话凭据。

## 五、已知限制

| 限制 | 说明 |
| --- | --- |
| 原生层 | 直接读 `/proc`、`/sys`、调用 `getprop` 二进制仍可绕过 |
| 未覆盖的包 | 只覆盖清单内的包，新增包需重编 |
| 检测点更新 | 应用新增检测点后需补充 hook |
| 系统差异 | 不同系统上部分 hook 点不存在，需容错 |
| 版本敏感 | 类名/方法签名随版本变动 |

## 六、反检测的根本矛盾

把上面所有技术细节抽掉，剩下一个结构性矛盾：

| 伪装行为 | 造成的可检测特征 |
| --- | --- |
| 属性全部改为原厂值 | 与系统实际行为不一致（例如企业 API 缺失） |
| 权限伪装为已授予 | 查询返回空数据，与「有权限」不符 |
| su 伪装为不存在 | 但系统镜像本身是第三方编译的 |
| 文件存在性全部 false | 但某些路径在第三方系统上确实存在 |

也就是说：**每补一个洞，就新增一个不一致。** 检测方只需要找「不一致」，而不需要找「假」。

这也是 [[research/postmortem]] §3.2 的核心：应用层伪装做得再完整，下层只要有一条独立观测通道，结论就翻转。

---

一句话概括：**伪装的极限不是「让人看不出来」，而是「让人看不出矛盾」——而后者的难度随伪装覆盖面上升，而不是下降。**
